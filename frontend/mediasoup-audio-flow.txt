To stream high-quality audio from a WebAudio source to a consumer using Mediasoup (Rust backend) and Mediasoup-Client, here is the chronological flow of necessary parts.

Since you are building a "silent disco" application, I have included specific configurations for high-quality music streaming (stereo, higher bitrate), as the defaults are often tuned for low-bandwidth speech.
1. Backend: Router Configuration (Rust)

When: Before creating any transports.
Why: You must explicitly define the codecs the router allows. For music, Opus is the standard.

rust
use mediasoup::router::RouterOptions;
use mediasoup::rtp_parameters::{RtpCodecCapability, MimeTypeAudio};

// In your worker initialization
let media_codecs = vec![
    RtpCodecCapability::Audio {
        mime_type: MimeTypeAudio::Opus,
        clock_rate: 48000,
        channels: 2, // Important for stereo music
        parameters: parameters, // e.g., sprop-stereo: 1
        ..Default::default()
    }
];

let router = worker.create_router(RouterOptions::new(media_codecs)).await?;

2. Frontend Producer: WebAudio Source Extraction

When: Before calling transport.produce().
Why: Mediasoup needs a MediaStreamTrack. Since you are using WebAudio (oscillators, files, or processed audio), you must bridge the AudioContext to a MediaStream.

typescript
// 1. Create your AudioContext and source
const audioCtx = new (window.AudioContext || window.webkitAudioContext)();
const sourceNode = ... // Your music source (BufferSource, Oscillator, etc.)

// 2. Create a specific destination node
const destination = audioCtx.createMediaStreamDestination();

// 3. Connect your graph to this destination
sourceNode.connect(destination);
// Optional: also connect to local speakers to monitor
// sourceNode.connect(audioCtx.destination);

// 4. Extract the track
const track = destination.stream.getAudioTracks()[0];

3. Frontend Producer: Producing the Stream

When: After the transport is connected.
Why: You need to tell Mediasoup how to encode this track. For music, we disable discontinuous transmission (DTX) and ensure stereo.

typescript
const producer = await producerTransport.produce({
  track: track,
  // Custom codec options to force stereo and high quality
  codecOptions: {
    opusStereo: true,
    opusDtx: false, // Don't cut silence for music
  },
  // Higher bitrate for music (default is usually ~32kbps for speech)
  encodings: [
    { maxBitrate: 128000 } // 128 kbps is usually sufficient for Opus stereo
  ],
  appData: { type: 'music' }
});

4. Backend: Handling Consumption (Rust)

When: The Consumer client requests to consume (via your signaling mechanism).
Why: The backend must link the specific producer_id to the new consumer.

rust
// 1. Receive request from client with rtp_capabilities and producer_id
let producer_id = ...; // From signaling
let rtp_capabilities = ...; // From client device.rtpCapabilities

// 2. Check if the router can actually consume this producer with these caps
if !router.can_consume(&producer_id, &rtp_capabilities) {
    return Err("Cannot consume".into());
}

// 3. Create the Consumer on the Transport
let mut consumer_options = ConsumerOptions::new(producer_id, rtp_capabilities);
consumer_options.paused = true; // Start paused! (Best practice)

let consumer = transport.consume(consumer_options).await?;

// 4. Send consumer.id, consumer.producer_id, consumer.kind, and
//    consumer.rtp_parameters back to the client via signaling

5. Frontend Consumer: Consuming the Stream

When: After receiving the consumer parameters from the backend.
Why: Creates the receiving side of the WebRTC connection.

typescript
const consumer = await consumerTransport.consume({
  id: serverParams.id,
  producerId: serverParams.producerId,
  kind: serverParams.kind,
  rtpParameters: serverParams.rtpParameters,
});

// Important: The consumer starts paused on the server (see Step 4).
// Once connection is established, tell server to resume.
await signaling.send('resumeConsumer', { consumerId: consumer.id });

6. Frontend Consumer: HTML5 Playback & Autoplay Policy

When: You have the consumer object.
Why: You must convert the Mediasoup track back into something an HTML <audio> element can understand, while handling browser Autoplay policies (the "Silent Killer" of audio apps).

typescript
// 1. Create a new MediaStream from the consumer's track
const stream = new MediaStream([consumer.track]);

// 2. Create or select an audio element
const audioParams = new Audio(); // or document.querySelector('audio')
audioParams.srcObject = stream;
audioParams.playsInline = true; // Required for iOS
audioParams.autoplay = true;

// 3. CRITICAL: Handle Autoplay Policy
// Browsers block audio unless triggered by user interaction (click/tap).
// If the AudioContext is suspended, nothing will play.

async function tryPlay() {
    try {
        await audioParams.play();
        console.log("Audio playing");
    } catch (err) {
        console.warn("Autoplay blocked, waiting for user interaction", err);
        // Show a "Click to Play" button in your UI
        document.getElementById('play-btn').onclick = () => {
             audioParams.play();
             // If using WebAudio API for playback processing:
             // if (audioCtx.state === 'suspended') audioCtx.resume();
        };
    }
}

tryPlay();

Summary Checklist for Success

    Codecs: Ensure channels: 2 is set in Rust media_codecs.

    Sample Rate: Ensure your WebAudio Context, Producer settings, and Consumer settings generally agree (Opus handles 48kHz internally, but avoid 44.1kHz <-> 48kHz resampling if possible for CPU efficiency).

    Bitrate: Set maxBitrate in the Producer encodings; otherwise, it defaults to a low bitrate meant for voice.

    Autoplay: Always assume audio.play() will fail on page load and have a fallback UI button ready.
